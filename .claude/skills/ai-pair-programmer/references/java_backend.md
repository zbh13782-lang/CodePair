# Java 后端范式

适用于 Java / Spring / Boot / 中间件常见后端实现。

## 1. 典型职责分层

- Controller / Facade：接收参数、入口校验、路由和响应适配
- Service / Manager：业务编排、状态流转、事务边界
- DAO / Repository：数据库访问
- Client / Adapter / Gateway：外部调用、协议转换、重试和错误翻译
- Converter / Assembler：对象转换，不要散落在业务主流程中

## 2. 设计原则

- 优先选择简单、明确、符合项目已有习惯的实现。
- 只有在策略、状态、流程稳定变更多时才考虑 Strategy / State / Factory 等模式。
- 不为了“设计模式”而增加过多抽象、接口和目录层级。
- 现有项目中已有扩展点时，优先复用它而不是新建并行体系。

## 3. Java 代码门禁

- 入口层不做复杂业务计算。
- 事务边界要清晰，不要把所有逻辑塞进一个大 Service 方法。
- 外部调用、副作用和协议转换收敛到适配层。
- 不要吞异常；要区分参数错误、业务失败、依赖失败和系统异常。
- 使用项目已有异常体系和错误码，不要随意抛裸 RuntimeException。
- DTO、VO、Param、Result、Enum 等命名要尽量沿用项目现有习惯。

## 4. 验证

- 运行相关 Maven / Gradle 测试
- 覆盖正常、边界、异常、幂等等关键路径
- 对事务、库存、支付、权限、消息等高风险链路重点说明回归点
